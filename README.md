# MyMusicLib

Локальный музыкальный каталог и плеер. Интерфейс работает в браузере; Node.js-сервис читает музыку из подключённых папок. Облачные сервисы для работы приложения не нужны.

## Запуск на Windows

Требуется **Node.js 24 LTS**.

Дважды нажмите **`start.bat`**. При первом запуске устанавливаются зависимости, затем запускаются сервер и клиент. Откройте **http://127.0.0.1:5173** вручную. Изменения интерфейса видны автоматически. Повторный запуск BAT проверяет уже работающий экземпляр и не открывает новый браузер.

Окно запуска должно оставаться открытым. Для остановки нажмите `Ctrl+C`. Клиент: порт 5173; локальный API: 4317. Приложение работает только на этом компьютере.

Для запуска собранной версии без режима разработки:

```powershell
npm ci
npm start
```

Она открывается на **http://127.0.0.1:4317**. После сборки можно запускать `npm run serve`.

## Desktop-сборка для Windows

Доступны два самостоятельных x64-дистрибутива:

```powershell
npm run desktop:installer # release\MyMusicLib-<version>-x64-unsigned-Setup.exe
npm run desktop:portable  # release\MyMusicLib-<version>-x64-unsigned-portable.exe
```

Installer устанавливает MyMusicLib только для текущего пользователя, не требует прав администратора и создаёт ярлыки на рабочем столе и в меню «Пуск». Portable EXE запускается без установки и не создаёт ярлыков. Для сборки обоих вариантов одной командой используйте `npm run desktop:dist`.

Desktop-версия запускает тот же локальный API на `127.0.0.1:4317` во внутреннем utility process. Закрытие окна скрывает приложение в tray; для полной остановки выберите «Выход». В tray также можно открыть интерфейс в обычном браузере. Повторный запуск показывает существующее окно и не создаёт второй backend.

Установленная beta-версия проверяет GitHub Releases, но не начинает загрузку и установку без явных кнопок пользователя. Portable обновляется вручную со страницы Releases. Пока приложение не подписано Windows-сертификатом, beta-файлы намеренно помечены `unsigned`: Windows может показать предупреждение SmartScreen.

Каталог, recovery и база обеих версий остаются в `%LOCALAPPDATA%\MyMusicLib`; Chromium-профиль Electron находится в `%LOCALAPPDATA%\MyMusicLib\electron`. Portable EXE не переносит эти данные вместе с собой. Удаление установленной версии намеренно не удаляет пользовательские данные. Для unpacked-сборки также поддерживается `MYMUSICLIB_DATA_DIR`:

```powershell
npm run desktop:pack
npm run test:desktop:smoke
release\win-unpacked\MyMusicLib.exe
```

## Публикация unsigned beta

Release workflow запускается только push-тегом вида `v0.x.y-beta.n`; тег должен в точности соответствовать `version` в `package.json`. Он выполняет проверки, собирает NSIS и portable, запускает packaged smoke и создаёт GitHub prerelease с updater-метаданными канала `beta`.

Перед выпуском обновите версию, прогоните `npm test` и desktop smoke, затем закоммитьте изменение, создайте тег и отправьте его:

```powershell
git tag v0.x.y-beta.n
git push origin main --tags
```

Не перемещайте и не публикуйте повторно существующий beta-тег. Реальную проверку обновления проводят двумя последовательными тегами: установить beta N, выпустить beta N+1, вручную скачать и подтвердить установку из приложения, затем проверить версию и сохранность библиотеки, каталога, закладок, журнала и recovery.

## Использование

1. Нажмите «Подключить папку» и укажите абсолютный путь, например `D:\Music\Downloads`. Подключите целевую папку коллекции отдельно.
2. Выбирайте библиотеки, жанры, исполнителей и альбомы. Нажатие на библиотеку раскрывает её папки; выбранная папка работает как рекурсивная мини-библиотека, а в панели остаётся открытой только одна ветка. Внутри остальных колонок значения объединяются, между колонками применяются совместно. Пустой выбор означает «Все».
3. Запускайте трек двойным щелчком или кнопкой слева от названия. Очередь фиксируется из текущего результата и не меняется при переключении фильтров.
4. Отметьте треки флажками. В панели над списком доступны теги, перенос и удаление. Перед изменением открывается предварительный просмотр.
5. В редакторе применяются только отмеченные поля. Несколько значений разделяются `;`. Очистка отмеченного поля удаляет его значение.
6. Для одного трека или полного альбома нажмите «Найти» в блоке MusicBrainz. Выберите издание вручную: пустые теги будут отмечены автоматически, а замену заполненных значений нужно включить отдельно. Обложка точного издания берётся из Cover Art Archive; запасная обложка группы релизов помечается предупреждением.
7. Журнал в правой части шапки показывает результат по каждому файлу. Из него можно восстановить удалённые файлы и исходные теги, а также повторить незавершённую операцию.

Альбомы занимают самую широкую колонку. Ширины меняются перетаскиванием границ. Используются Lucide и три размера текста: 14, 16 и 24 px.

## Данные и сохранность файлов

- Windows: `%LOCALAPPDATA%\MyMusicLib`; macOS: `~/Library/Application Support/MyMusicLib`; Linux: `$XDG_DATA_HOME/MyMusicLib` или `~/.local/share/MyMusicLib`.
- `catalog.sqlite` — каталог, очередь и журнал; `covers` — кэш обложек; `recovery` — удалённые файлы и резервные копии перед записью тегов.
- `MYMUSICLIB_DATA_DIR` задаёт другой каталог данных; `MYMUSICLIB_PORT` — порт собранного сервера; `MYMUSICLIB_NO_OPEN=1` отключает автоматическое открытие браузера.
- Область восстановления не очищается автоматически. Не удаляйте её, пока нужны резервные копии. Удаление из приложения переносит файл сюда, а не в системную корзину.
- Перенос сохраняет относительный путь, сверяет SHA-256 копии и только затем удаляет исходник. Существующие файлы не перезаписываются.
- Запись тегов выполняется на временной копии. Проверяются исходный файл, аудиоданные, неизменённые метаданные и результат записи. Исходная копия сохраняется для восстановления.
- Файлы, изменённые другим приложением после предварительного просмотра, пропускаются. Для них обновите библиотеку и создайте новый просмотр.
- После аварийного завершения операция отмечается как прерванная. «Повторить незавершённые» сверяет записанные хэши и завершает безопасные шаги; конфликтующие или повреждённые копии требуют проверки и не перезаписываются.
- Сервис не держит постоянные наблюдатели за музыкальными папками. Он сканирует их при старте и каждые пять минут. Кнопка обновления библиотеки перечитывает также теги и обложки.
- Поиск MusicBrainz выполняется только по явной кнопке и передаёт сервису введённые название и исполнителя. Результаты кэшируются локально; ручное редактирование и воспроизведение не требуют сети.
- При операции над проигрываемым треком поток закрывается; после операции воспроизведение продолжается с прежней позиции. После удаления трек останавливается.

Не перемещайте файлы одновременно из нескольких программ. Проверки обнаруживают изменения между этапами, но не заменяют резервное копирование при отказе диска или системы.

## Проверки

Все файловые тесты используют созданные тестовые аудиофайлы и отдельные каталоги. Пользовательские библиотеки в них не участвуют.

```powershell
npm run fixtures
npm run verify:tags
npm test
npm run test:e2e
npm run benchmark
```

`verify:tags` создаёт `verification/tag-support.json`. Редактор разрешён только для форматов, прошедших проверку с установленной версией библиотеки записи. Проверяются MP3 (ID3v2.3/2.4), FLAC, M4A, AAC, Ogg Vorbis, Opus и WAV: кириллица, множественные значения, большие обложки, сохранность неизвестных тегов, SHA-256 аудиоданных и независимое декодирование через FFmpeg.

Браузерные тесты используют установленные Chrome и Edge. Они проверяют воспроизведение всех форматов, перемотку, теги во время воспроизведения, переносы и восстановление. Снимки находятся в `.test-data/`.

`benchmark` проверяет синтетическую базу из 100 000 треков / 10 000 альбомов и виртуализацию в Chrome. Это **не измерение импорта 100 000 реальных файлов**. Результат: `verification/catalog-benchmark.json`.

## Структура и дальнейшие этапы

- `src/client` — React, TanStack Query/Virtual, браузерный плеер.
- `src/server` — Fastify, SQLite, очередь операций, два рабочих потока для тегов и хэширования, ограниченный клиент MusicBrainz/Cover Art Archive.
- `src/shared/contracts.ts` — типы и схемы API.
- `docs/ROADMAP.md` — этапы разработки, границы и ограничения.
- `THIRD_PARTY_NOTICES.md` — сведения о стороннем коде.

Поддержка macOS/Linux архитектурно предусмотрена; текущие проверки выполнены на Windows. AcoustID/Chromaprint, сетевой доступ к самой библиотеке и gapless в эту версию не входят. Windows desktop shell выпускается как NSIS installer и portable EXE; интерфейс и механизм автообновлений остаются следующим этапом.

Порядок колонок: библиотеки → жанры → исполнители → альбомы → треки. Исполнитель и форматы отображаются у группы альбома; строки треков содержат только номер, название и длительность.
