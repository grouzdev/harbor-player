# Выжимка коммитов

Готовь выжимку по истории Git для одной даты или диапазона дат. Результат
должен быть полезен читателю, который не открывает каждый diff: перечисляй
все коммиты, их время и кратко объясняй результат каждого изменения.

## Входные данные и границы дня

- Пользователь может указать дату (`30.09.2026`) либо включительный диапазон
  (`28.09.2026–30.09.2026`).
- Если ref не указан, используй `HEAD`. Если пользователь просит конкретную
  ветку, тег или ревизию, используй только историю, достижимую из этого ref.
- Операционный день `YYYY-MM-DD` начинается в `05:00:00 MSK` этой даты и
  заканчивается **до** `05:00:00 MSK` следующей даты. MSK — это фиксированный
  UTC+03:00.
- Принадлежность коммита дню определяй по **дате коммиттера**. Она отражает
  создание именно этого объекта коммита, в том числе после `rebase` или
  `cherry-pick`; не смешивай её с датой автора.
- Начальная граница включительна, конечная — исключительна: коммит ровно в
  `05:00` относится к начинающемуся в этот момент дню.

Для дня `2026-09-30` интервал выглядит так:

```text
>= 2026-09-30T05:00:00+03:00
<  2026-10-01T05:00:00+03:00
```

## Сбор списка

1. Убедись, что ref существует и указывает на коммит:

   ```bash
   git rev-parse --verify --end-of-options 'HEAD^{commit}'
   ```

   Подставь пользовательский ref вместо `HEAD`. Если ref не существует,
   остановись и запроси корректный ref.

2. Получи кандидатов строго в нужном интервале. Используй ISO 8601 с
   `+03:00`, а не относительные выражения (`yesterday`, `midnight`) и не
   локальную часовую зону машины:

   ```bash
   git log HEAD \
     --since-as-filter='2026-09-30T05:00:00+03:00' \
     --before='2026-10-01T05:00:00+03:00' \
     --date=iso-strict \
     --format='%H%x09%h%x09%ct%x09%cI%x09%an%x09%s%x09%P'
   ```

   - Подставь ref и вычисленные границы для каждого дня или одного общего
     интервала диапазона.
   - `--since-as-filter` обязателен: в отличие от `--since` он не прекращает
     обход истории на старом родителе и не скрывает свежий коммит в ветке с
     неупорядоченными датами.
   - `%ct` и `%cI` — соответственно Unix-время и ISO-дата **коммиттера**.
     Проверяй, что каждый отобранный `%cI` действительно попадает в интервал;
     при сомнении в поведении Git фильтруй кандидатов по `%ct` относительно
     границ `02:00:00Z` (это `05:00 MSK`).
   - Не добавляй `--no-merges`: merge-коммиты — такие же коммиты отчёта.

3. Отображай время в Москве. Не полагайся на `TZ=Europe/Moscow` в Git Bash:
   на Windows его база зон может отсутствовать или вернуть неверное имя зоны.
   Используй Node.js и встроенный `Intl`:

   ```bash
   node --input-type=module -e "
   const seconds = Number(process.argv[1]);
   console.log(new Intl.DateTimeFormat('ru-RU', {
     timeZone: 'Europe/Moscow',
     hour: '2-digit',
     minute: '2-digit',
     hourCycle: 'h23',
   }).format(new Date(seconds * 1000)));
   " -- 1790781408
   ```

   Подставь `%ct` коммита вместо примера. Для нескольких коммитов допускается
   один вызов скрипта, но преобразование всегда должно выполняться через
   `timeZone: 'Europe/Moscow'`.

4. Для каждого коммита изучи сообщение, изменённые файлы и статистику:

   ```bash
   git show --no-ext-diff --format=fuller --stat --summary <full-hash>
   ```

   Если этого недостаточно для верного смысла, просмотри патч:

   ```bash
   git show --no-ext-diff --format=fuller --find-renames <full-hash>
   ```

   Для merge-коммита сначала посмотри его родителей и сообщение. Описывай
   результат слияния; не интерпретируй объединённый diff как обычную
   самостоятельную реализацию. При необходимости используй
   `git show --first-parent --stat <full-hash>`.

## Как писать описание

- Не копируй автоматически subject: он может быть неточным или слишком общим.
- Напиши одно короткое законченное предложение о том, что изменилось для
  пользователя, продукта или разработки. Добавь второе только если без него
  теряется существенная часть изменения.
- Предпочитай результат реализации внутренним деталям. Например:
  `Сохраняет выбранные фильтры каталога при выполнении поиска`, а не
  `Обновляет state в CatalogPanel`.
- Не придумывай намерения, поведение или результаты, которых нет в diff.
- При нескольких независимых изменениях в одном коммите перечисли их
  компактно через точку с запятой.

## Формат ответа

Отсортируй коммиты внутри дня по времени по возрастанию и сгруппируй по
операционным датам. Всегда указывай MSK:

```md
## 30 сентября 2026 — 05:00–05:00 MSK

- `2eff9af` — 18:09 — Сохраняет выбранные фильтры каталога при выполнении поиска.
- `70eb8a3` — 18:16 — Поиск применяет выбранные значения как фильтры каталога.
```

- Для диапазона создай такой раздел для каждого запрошенного дня, включая дни
  без изменений.
- Для пустого дня напиши `Коммитов нет`.
- Не включай коммиты за пределами достижимой истории выбранного ref.
- Если checkout является shallow-клоном или история явно неполна, предупреди
  об этом до отчёта: результат может не содержать старые коммиты.
