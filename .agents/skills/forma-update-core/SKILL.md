# Обновить ядро Forma

## Найти установку и инструмент

1. Прочитай местные `AGENTS.md` и инструкции задачи. Работай только в выбранном
   подключённом репозитории, не в основной копии или соседнем проекте.
   Зафиксируй абсолютный путь его корня как `REPO`; посмотри текущий Git diff,
   чтобы не присвоить и не затереть чужие изменения. Не делай commit, merge или push.
2. Прочитай `.forma/state.json`: `directory` задаёт каталог страниц `PAGES`,
   `bundle.revision` — установленную редакцию, `bundle.source` — источник,
   `bundle.format` — размещение, `bundle.locale` — язык (`ru` для старого формата 1).
   Не редактируй состояние вручную. При отсутствии или неизвестном формате
   остановись с конкретной причиной; не заменяй обновление на `init`.
   Прочитай установленное ядро в `PAGES/core/core.md` либо `PAGES/Ядро/Ядро.md`
   для старого размещения. `.forma` — каталог на момент поставки этого skill;
   если он расходится с состоянием, сначала выясни причину.
3. Если есть `.forma/pending.json`, обычное обновление запрещено.
   Сообщи о незавершённом переходе и предложи штатный `recover --dry-run`;
   не удаляй журнал и не восстанавливай работающий процесс.
4. Найди локальную утилиту Forma по явному пути пользователя или документации
   проекта. Не ищи по всему диску и не записывай машинный путь в этот skill.
   Если путь неизвестен или доступно несколько разных копий, спроси пользователя.
   Проверь её инструкции, `package.json` и документацию обновления.
   Нужны Node.js 24+ и подготовленные зависимости самой Forma.
   Не устанавливай зависимости в приложение. Недостающие зависимости, скачивание,
   `git pull` и выбор другого источника требуют отдельного разрешения.

## Показать переход

Все команды ниже выполняются **из корня локальной Forma**, не проекта.
Подставляй абсолютные пути вместо `REPO` и `PAGES`; заключай пути в кавычки.
В PowerShell при запрете `npm.ps1` используй `npm.cmd`.

```sh
npm run forma -- update --repo "REPO" --dry-run
```

Без указанного пользователем выпуска используется набор по умолчанию именно
этой локальной утилиты, а не «последний из интернета». Утилита берёт язык и
каталог из состояния. Если пользователь выбрал конкретный набор, прочитай его
`release.json` и добавь `--bundle "АБСОЛЮТНЫЙ_ПУТЬ_НАБОРА" --to РЕДАКЦИЯ`.
Не выбирай версию сортировкой имён каталогов и не обновляй старые выпуски на месте.

Покажи текущую и целевую редакции, источник, язык, каталог, изменения правил,
влияние на местные правки и skills, полный доступный diff и хеш плана.
Одинаковая редакция может означать обновление входов skills, а не новое ядро.
Если изменений нет, так и заверши. При конфликте, несовместимости или ошибке
остановись; не обходи проверку ручным копированием, правкой метаданных или `--force`.
Смена языка, размещения или источника — отдельная миграция.

## Применить и проверить

Получи подтверждение показанного перехода; сам вызов skill не утверждает
неизвестный заранее diff. После подтверждения повтори ту же команду со всеми
параметрами, заменив `--dry-run` на `--apply ХЕШ`. Не придумывай хеш.
Если план изменился, покажи новый предпросмотр и получи новое подтверждение.
При ошибке не объявляй успех и не запускай автоматический откат поверх правок.

После успешного применения перечитай состояние и итоговый Git diff.
Проверь страницы установленным CLI:

```sh
npm run forma -- check "АБСОЛЮТНЫЙ_ПУТЬ_К_PAGES"
```

Убедись, что продуктовые страницы, граф, код и зависимости приложения не изменены
этой операцией. Не запускай обновление карты или смысловую миграцию автоматически.
Для отката последнего успешного обновления есть:

```sh
npm run forma -- rollback --repo "REPO" --dry-run
```

Это только предпросмотр; применение отката тоже требует подтверждения и хеша.
Поздние пересекающиеся правки могут блокировать откат. После прерванной записи
используется `recover`, а не удаление `.forma/`.

Заверши отчётом: откуда и до какой редакции обновлено, какие входы изменились,
что сохранено, точные команды и результаты проверок, ограничения и способ отката.
Не называй структурную проверку доказательством правильности новых правил.
