# Готовность CI до следующего релизного тега

Источник: grouzdev в Delta поручил исправить все оставшиеся проблемы после
неудачного выпуска beta.3. Согласован общий разбор E2E вместо нового
beta-тега после каждого исправления. Версию и существующие теги не меняем.
Отправка в main и выпуск требуют отдельного подтверждения; сначала проверка
на рабочей ветке.

## Исходные свидетельства

На `a07d7bf` прежние регрессии Пульса и владения SQLite прошли в CI.
Release run `41220287108`: Chrome 170/172, ошибки проверки переноса в плейлист
и Home в режиме обложки. Main run `41220287129`: модульные проверки прошли,
Chrome 171/172, исчез пункт контекстного меню в сценарии файловых операций.
Все три сценария проходят локально без замедления.

## План и критерий

Воспроизвести ошибки через контролируемые задержки/замедление, отделить
неверную синхронизацию тестов от ошибок приложения. Не скрывать проблемы
повторами или повышением тайм-аутов. Сохранять trace/screenshot/report при
падении в CI. Полный набор Chrome и Edge должен запускаться на рабочей
ветке до отправки следующего релизного тега.

## Реализация

Диагностический коммит `187f6e1` отправлен только в
`fix/ci-release-readiness`, без изменений main и тегов.
CI этой ветки (`41238378884`) повторил исчезновение контекстного меню,
но теперь сохранил trace и screenshot. В trace после выбора библиотеки
идут запросы каталога, затем RMB-выбор запускает relevance/validity и
восстановление позиций. Старое меню закрывалось от любого scroll любого
элемента, включая программные обновления панелей.

- Меню больше не закрывается от программного scroll. Сохраняются Escape,
  resize и внешний pointerdown; внешний wheel закрывает меню, drag scrollbar
  покрывается pointerdown. Автофокус меню/подменю использует preventScroll.
  Новая регрессия сначала упала на старом коде после программной прокрутки.
- В двух drag-тестах и тесте вставки `{}` заменён корректным PlaylistDetail.
  Старые ответы нарушали Zod-контракт и обходили refresh через ошибку.
  Между переносами ожидается снятие блокировки; отдельный gate удерживает
  refetch после POST и проверяет, что действия всё ещё заблокированы.
- В файловом сценарии перед RMB ожидается окончание загрузки альбомов,
  затем используется настоящий правый клик с проверкой preventDefault.
  Для загрузки добавлена aria-busy на поверхность альбомов.
- Реальный правый клик выявил CSS-дефект: hover был специфичнее drop-target
  и скрывал усиление яркости цели drop. Приоритет селектора исправлен,
  прежняя проверка brightness(1.18) сохранена.
- Готовность аудио больше не подменяет факт запуска. В сценарии обложки
  loadedmetadata удерживается явным gate после readyState >= 2: аудио ещё
  paused. После release тест ждёт реального play и нажимает кнопку паузы.
  Это исключает поздний автозапуск короткой фикстуры во время навигации.
- CPU-стресс выявил ещё одну гонку теста: серии синтетических dispatchEvent
  отправляли следующий клик до применения предыдущего React-выделения.
  Добавлены проверки промежуточных состояний без sleeps и retries.

Полный E2E включён для PR и веток `fix/ci-*`; раньше PR проверял только
smoke. CI и release workflows сохраняют test-results/playwright-report
на 7 дней, Playwright пишет HTML, список тестов и screenshot при ошибке.
Для двух файлов с проблемными сценариями доступен контролируемый CPU-стресс:
`HARBOR_PLAYER_E2E_CPU_RATE=6 npx playwright test ...`.
CPU-замедление не включает retries и не повышает тайм-ауты.

На `7eb5464` локально прошли `npm test` (562/562), полный
`npm run test:e2e` (Chrome 173/173, Edge 173/173), lint и format:check.
