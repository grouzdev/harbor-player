# Перетаскивание в плейлист

Источник: grouzdev в Delta попросил показывать будущие плашки и переносить
только выделение панели-источника. После исследования разрешил реализацию,
включая общую защиту мутаций, проверку переносов, очистку маркера вставки,
совместимость с рамкой и порядок элементов по списку.

## Правило и границы

В `dragstart` фиксируются тип и ID из одной панели. Выделенный источник
переносит выделение этой панели в порядке данных списка; невыделенный — только
себя. Другие фильтры и выделения не меняются. Drop не перечитывает состояние
каталога. Превью использует визуальную часть плашки плейлиста: первые три
элемента и «Ещё N». Неизвестная длительность не заменяется нулём.

Добавление, перестановка и удаление используют одну блокировку до завершения
запроса и обновления данных. Неподдерживаемые переносы не принимаются.
Вложенная строка остаётся целью вставки перед владеющей сущностью, не внутрь.
Перетаскивание без модификаторов со строки не начинает рамку; начало нативного
drag отменяет незавершённый жест рамки.

Код: `catalog-drag.tsx`, `PlaylistEntityCopy.tsx`, источники каталога,
`PlaylistPanel.tsx`, `PlaylistContent.tsx`, `panel-selection.tsx`.
Серверная модель, повторы, перенос папок, публикация и слияние не входят.

## Проверка

Реализовано в рабочем дереве поверх `f240188`, без слияния и публикации.

- `npm test` — 534 теста в 67 файлах прошли; из них 15 новых проверяют
  порядок, отдельный невыделенный источник, пустой жанр, валидацию и визуальную часть.
- `npm run build` — прошёл, включая `typecheck` и desktop-компиляцию.
- `npm run lint` — прошёл.
- `npx playwright test tests/browser/playlist-panel.spec.ts --project=chrome --project=edge`
  — 24 запуска прошли, включая вставку перед владельцем вложенного трека,
  общую блокировку добавления/удаления, отказ посторонним переносам и очистку маркера.
- `npx playwright test tests/browser/catalog-navigation.spec.ts --project=chrome --project=edge --grep 'playlist drag'`
  — 4 запуска прошли. Проверены одновременное выделение в разных панелях,
  снимок независимо от последующих кликов, все четыре типа источника,
  реальный перенос мышью, три плашки и «Ещё 1» для четырёх треков.
- `npx playwright test tests/browser/library.spec.ts --project=chrome --project=edge --grep 'panel selection supports Shift ranges and bounded marquee drag'`
  — 2 запуска прошли.
- Prettier для изменённых TS/TSX/CSS и `git diff --check` — прошли.

Общий прогон двух браузерных файлов (116 запусков) не завершён:
остановлен ограничением 200 секунд после тайм-аутов старых сценариев навигации.
Отдельный запуск `plain library click preserves upstream ... library filter`
с `--timeout=10000` подтвердил ожидание отсутствующей кнопки с точным именем
«Добавить фильтр». В неизменённом `CatalogUserFilters.tsx` уже на `HEAD`
используются кнопки «Добавить фильтр «…»». Согласование этих тестов с текущими
фильтрами не входит в этот фикс; полный E2E не объявляется зелёным.

Ручная визуальная приёмка в Electron и упаковка установщика не выполнялись.
Браузерная проверка подтверждает передачу размеченного превью в `setDragImage`
при реальном drag, но не является ручной оценкой изображения под курсором.

## Доработка читаемости превью

Источник: grouzdev показал скриншот — нативное полупрозрачное изображение
почти не различимо на фоне каталога. По его просьбе превью заменено
непрозрачной DOM-плашкой рядом с курсором, а нативное изображение скрыто.
Белые названия, светлые подписи и иконки, контрастная рамка и заголовок
«В плейлист · N» отделяют перенос от фона. Сохраняются первые три записи
и «Ещё N», состав и порядок не меняются.

Плашка следует событиям drag/dragover, удерживается в границах окна и убирается
при drop, dragend, Escape, потере фокуса или начале следующего переноса.
Обновлённый браузерный сценарий проверяет саму видимую плашку до отпускания
мыши: непрозрачный фон, белый текст, одиночный и множественный перенос,
очистку после завершения и отмены.

Проверки этой доработки: `npm run build` (включая typecheck), `npm run lint`,
`npm test -- tests/catalog-drag.test.ts` (15 тестов), браузерные сценарии
`playlist drag` в Chrome/Edge и `git diff --check`. Получен и просмотрен
скриншот непосредственно во время реального браузерного drag: плашка читается
на фоне приложения. Полный набор модульных/E2E-тестов после этой визуальной
доработки заново не запускался; ручная проверка в Electron не выполнялась.

### Более спокойное оформление

По следующему отзыву grouzdev убраны заголовок «В плейлист» и яркая
акцентная рамка. Сохранены непрозрачный фон и читаемые подписи; рамка стала
тонкой и приглушённой. Теперь видны до пяти записей, «Ещё N» появляется
только с шестой. Браузерная регрессия проверяет границу: пять без сворачивания,
шесть — пять плашек и «Ещё 1», без заголовка.
