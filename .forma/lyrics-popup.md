# Тексты песен

Источник — grouzdev в Delta: поиск обычных текстов для чтения и запись в теги.
Парсинг сайтов, синхронизация, таймкоды и подсветка исключены. Основные форматы
коллекции — MP3 и FLAC. После HTML-мокапа пользователь выбрал минималистичный
попап вместо боковой панели и запретил статичные поясняющие текстовые лейблы.
Затем поручил реализовать функцию. Публикация и landing не поручены.

## Поведение

Кнопка в плеере открывает текст выбранного на этот момент трека. При смене
очереди открытый попап остаётся привязан к прежнему треку: его заголовок,
редактирование и сохранение не перескакивают на другую песню.
Локально сохранённый выбор имеет приоритет перед встроенным текстом.
Если текста нет, открытие автоматически запускает поиск и запись в теги.
Источник уточнения — grouzdev в Delta: поиск при открытии попапа, сохранение
сразу в MP3/FLAC, существующий текст не заменять, неоднозначности выбирать вручную.

По дополнительной просьбе grouzdev пункт «Текст» в RMB-меню трека открывает
тот же попап для нажатого трека, не меняя очередь и воспроизведение.
При множественном выделении это одиночное действие для трека под курсором,
без суффикса количества. Состояние попапа общее для меню и плеера.
Повторная проверка лицензирования и основания записаны в
`docs/lrclib-licensing.md`: разрешение на контент не подтверждено.

Поиск выполняется через backend в LRCLIB при открытии попапа без текста;
ручной поиск другого текста также доступен. Используется только `plainLyrics`.
Для автоматического выбора нужны точные совпадения названия, исполнителя
и непустого альбома после нормализации регистра/пробелов, длительность ±2 секунды.
Если подходящих записей несколько, автоматический выбор допустим только
при одинаковом тексте; при разных текстах или отсутствии точного совпадения
показаны варианты. Выбор варианта для пустого файла также сразу записывает текст.
Порог и критерии — консервативное инженерное решение агента, не гарантия
правильности содержимого провайдера. При неполных метаданных не угадываем.
Инструментальные результаты и результаты без обычного текста выбрать нельзя.
Ошибки и отсутствие результатов показываются как состояние, без статичных
инструкций. Доступные имена и всплывающие подсказки у кнопок сохраняются.

«В Harbor» записывает текст в SQLite отдельно от аудиофайла.
Если локальный выбор уже существует, последующая успешная запись текста в файл
обновляет и его, чтобы старая копия не перекрывала только что сохранённый текст.
Автоматическая запись использует preview существующей операции тегов,
но не требует дополнительного подтверждения. «В файл…» для ручных правок
и замены уже сохранённого текста по-прежнему ждёт подтверждения.
Успех показывается только после завершения job без ошибок.
Для текста отключён быстрый in-place writer: запись идёт через staging
с проверкой аудиоданных и остальных тегов; резервирование зависит от настроек.
Запись ограничена MP3 (`USLT`) и FLAC (`LYRICS`) и действующим capability gate.
Замена MP3-текста заменяет все обычные `USLT`, не синхронизированные кадры.
Для автоматических операций сохраняется флаг `lyricsOnlyIfMissing`:
текст проверяется в верифицированной staging-копии, а локальная копия —
также непосредственно перед заменой. Изменение исходника обнаруживается
обычной проверкой хеша. Повтор незавершённой операции сохраняет этот запрет.
Одновременные автоматические открытия одного трека объединяются на backend.
Закрытие попапа отменяет ожидание клиентом, но уже запущенная запись может
завершиться в фоне; повторное открытие прочитает её результат.

## Сеть и ограничения

LRCLIB получает исполнителя и название при открытии попапа без текста
или при ручном поиске. Открытие уже сохранённого текста не обращается к LRCLIB.
Клиент выполняет запросы последовательно с интервалом, ограничивает размер
ответа, проверяет JSON-контракт и соблюдает `Retry-After`. Результаты поиска
кешируются в памяти на пять минут; не более 50 запросов.
Секретные ключи и парсинг HTML не используются.

Условия лицензирования самих текстов, их показа, локального хранения и записи
в теги остаются невыясненными. Доступность API не подтверждает этих прав.
Это остаточная неопределённость, а не установленный запрет или обязательное
требование получить письменное разрешение перед выпуском.

Исходники: `src/client/LyricsDialog.tsx`, `src/server/lyrics.ts`,
`src/shared/lyrics.ts`, маршруты в `app.ts`, хранение в `database.ts`,
запись в `tag-writer.ts` и `mp3-id3.ts`.

Изменения проверены поверх `eb6877a`, версия проекта `0.4.1-beta.4`.

- `npm run build` — успешно, включая TypeScript, backend, desktop и Vite.
  Попап загружается отдельным lazy chunk.
- `npx vitest run tests/lyrics.test.ts tests/service.test.ts tests/api.test.ts tests/catalog-persistence.test.ts tests/musicbrainz.test.ts tests/tag-writer-capabilities.test.ts`
  — 114 успешных проверок.

  — 18 успешных проверок.

  `react-hooks/exhaustive-deps` в эффекте Media Session у `Player`.
- Prettier для изменённых TS/TSX/CSS и `git diff --check` — успешно.

Проверены реальные записи и замены обычного текста в MP3 ID3v2.3, ID3v2.4,
MP3 без исходного ID3v2 и FLAC; неизменность аудиоданных и остальных тегов,
сохранение текста при чужой правке тегов и восстановление исходных байтов
при включённых резервных копиях. Проверены локальное хранение после открытия
базы заново и доступ к нему после исчезновения музыкального файла.

В браузерах проверены встроенный текст, отсутствие автоматического поиска,
выбор результата, ручная правка, сохранение локально и в настоящий FLAC,
отмена замены, ошибки и пустой поиск, закрытие/возврат фокуса,
повторное чтение без устаревшего query cache и окно шириной 700 px.

не испытывался. Его предварительная проверка описана в обсуждении.

Промежуточный прогон выявил скрытую в компактном плеере кнопку:
она перенесена из скрываемой группы громкости к информации о треке.
Одна проверка паузы первоначально выполнялась до окончания загрузки audio;
тест исправлен ожиданием начала реального воспроизведения перед паузой.
Повторный прогон успешен.

Полные наборы тестов и ручная приёмка в Electron не выполнялись.
Поддержка всех сторонних плееров, полнота LRCLIB и права на тексты
не подтверждены. Публикация и Git landing не выполнялись.

## Дополнение: контекстное меню и условия LRCLIB

После добавления пункта «Текст» повторно выполнены `npm run build`
и `npx playwright test tests/browser/lyrics.spec.ts tests/browser/player-value-bubble.spec.ts --project=chrome --project=edge`
— сборка успешна, 20 браузерных проверок прошли.
Новый сценарий проверяет открытие текста без запущенного трека и при
множественном выделении, выбор именно нажатой песни при другой песне
в плеере, неизменность audio source и паузы, а также повторное открытие
текста текущей песни кнопкой плеера.

ESLint для `App.tsx`, `Player.tsx` и браузерного теста — без ошибок,
с предупреждениями о зависимостях существующих хуков; `git diff --check`
успешен. Модульные тесты на этом шаге повторно не запускались:
backend и запись тегов не менялись.

По публичным первоисточникам доступ к API разрешён, но лицензия на тексты
для показа, постоянного хранения и записи в теги не подтверждена.
PR с юридическими правилами не принят и не является действующими условиями.
Владельцу сервиса не писали; перечень вопросов для письменного уточнения
сохранён в `docs/lrclib-licensing.md`.
