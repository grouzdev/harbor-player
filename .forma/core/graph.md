# Смысловой граф

**Связываем объяснение проекта, утверждения и основания. Не угадываем истину.**
Следуем [[core|ядру]] и [[update-state-map|процессу обзора]].
Это форматы `forma-graph/0.1` и `0.2`, не изменение [[notation|грамматики страниц]].

## Точная схема

Из локальной Forma получи `npm run forma -- graph schema --version 0.2`.
Без `--version` выводится прежняя схема `0.1`; не добавляй в неё новые поля молча.
Фрагменты `<PAGES>/graph/*.json` небольшие, без вложенных каталогов.
Все ID источников, областей, узлов и связей уникальны во всём графе.
У `0.1` обязательны `format`, `sources`, `scopes`, `nodes`, `edges`.
У `0.2` дополнительно обязателен `entries` — список ID понятий начального слоя.
Пустой список допустим для схемы, но не заменяет понятный вход в обзор.
Обе версии могут сосуществовать. Не создавай страницу на каждую карточку.

## Предметы и утверждения

Узел: `{id, role, label, scope, content, author, acceptance, provenance, run}`.
В `0.2` дополнительно обязателен `summary`: `null` или `{text, provenance}`.
Текст 1–1200 символов, непустые основания даже у гипотезы.
Это короткая суть, не повтор названия. `null` означает отсутствие объяснения.
У `0.1` объяснений нет; просмотрщик не сочиняет их из подписи.

Роли: `concept`, `requirement`, `scenario`, `decision`, `implementation`,
`check`, `observation`, `question`; `concept` доступен только в `0.2`.
Понятие — предмет проекта, не правило и не автоматически принятая идея.
Цели и направления записывай как `requirement`, риски — `observation` с пояснением.
У требования и решения `acceptance`: `unknown`, `proposed`, `accepted`,
`superseded`, `rejected`; три последних требуют негипотетических оснований.
У остальных `not-applicable`. `scope` — обоснованный вариант программы или `null`,
не папка и не приоритет. `author` — известный автор утверждения или `null`.
`content` ссылается на источник содержания. Неизвестные значения не выдумывай.

Связь: `{id, from, to, relation, provenance}`:

- `about`: любой узел → `concept`; утверждение относится к предмету.
- `elaborates`: `concept` → `concept`; более подробный предмет раскрывает общий.
- `accepts`: decision → requirement; `implements`: implementation → requirement/scenario.
- `verifies`: check → requirement/scenario; `result-of`: observation с run → check.
- `supports`, `contradicts`: observation → requirement/scenario/decision/implementation.
- `supersedes`: decision → decision; циклы замены запрещены.

Первые две связи доступны только в `0.2`, самоссылки запрещены.
Одна сущность участвует в разных представлениях без копирования.
Связь не назначает принятие и не устраняет противоречия. Навигационная wiki-ссылка
сама по себе не становится типизированной связью.

## Источники и происхождение

Источник: `{id, locator}`. Локатор — ровно один из:
`{path, lines, sha256}`, `{page, heading, sha256}`, `{url}`.
Путь — от корня репы, page — устойчивый ID страницы; heading — точный заголовок
или `null`; lines — `{start, end}` включительно или `null`.
Хеш — SHA-256 всего UTF-8 файла после CRLF → LF, либо `null`.
Для `0.2` доступен `{path, media: "image", sha256}` с хешем исходных байтов.
Безопасный просмотр изображений ограничен PNG/JPEG до 2 МиБ, 8192 px и 16 Мп.
URL не скачивается. Не закреплённый хеш виден как `unpinned`.

`provenance`: `{recordedBy, recordedAt, basis, evidence, reviewedBy, reviewedAt}`.
Время — UTC `YYYY-MM-DDTHH:mm:ssZ`; basis — `hypothesis`, `sourced`, `reviewed`.
Для двух последних нужны источники; для `reviewed` — участник и время проверки,
иначе поля проверки равны `null`. В этой операции даже гипотезе нужно основание.
Автор записи и автор утверждения — не одно и то же. Подпись не цифровое удостоверение.

Только наблюдение о запуске имеет `run`:
`{command, executedBy, executedAt, environment, commit, worktree, result, inputs}`.
`commit` — полный Git SHA или `null`; `worktree`: `clean`, `dirty`, `unknown`;
`result`: `passed`, `failed`, `inconclusive`; `inputs` — ID источников состояния.
Ровно одна `result-of` ведёт к проверке в той же области. У других узлов `run: null`.
Команда — текст свидетельства; просмотрщик её не исполняет.
Старый успешный запуск не доказывает готовность нынешнего кода.

## Проверить и читать

Из локальной Forma:

```sh
npm run forma -- graph check --repo "REPO" --pages "PAGES"
npm run forma -- graph check --repo "REPO" --pages "PAGES" --require-summaries --format json
npm run forma -- graph layer --repo "REPO" --pages "PAGES" --format json
npm run forma -- graph view --repo "REPO" --pages "PAGES"
```

Сам добавляй `--allow-source src --allow-source tests` для изученных безопасных областей.
Без разрешений внешние исходники получают `unavailable`. Git-списки читаются локально.
Запрещены выход из репы, symlink/junction, hardlink, секреты, игнорируемые данные,
личные каталоги, зависимости и сборки. Имя файла не гарантирует отсутствие секретов.
Никогда не открывай весь диск ради основания.

Без фокуса слой показывает `entries`, а при их отсутствии — прежние узлы по ID.
У понятия `--detail 0` показывает прямые раскрытия и утверждения `about`,
`1` добавляет шаг реализации/свидетельств, `2` раскрывает следующий уровень.
`--id ID` выбирает фокус; у обычного узла показываются прямые связи.
По умолчанию limit 24, offset 0. `--search` ищет глобально, `--scope` фильтрует вариант.
Выбор воспроизводим, не ранжирует истинность и ничего не записывает.

`graph check` без нового флага допускает старые графы и `summary: null`.
`--require-summaries` проверяет всю карту: пропуски и пустой граф дают код 2,
JSON содержит `summaryCoverage` с total, filled и missing ID.
`--strict` даёт код 2 при любых диагностиках; ошибка структуры — 1.
Обычный код 0 допускает предупреждения. `forma check` проверяет страницы, не граф.
Совпавший хеш не доказывает смысл; изменённый требует пересмотра, не означает провал кода.
Не обновляй хеши ради зелёной проверки. Отсутствие связи означает «не записано».
