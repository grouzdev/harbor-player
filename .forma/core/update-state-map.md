# Обновить карту состояния

**Объясни проект человеку, затем свяжи объяснение с основаниями и текущим состоянием.**
Это полный верхний обзор, не опись файлов, доска всех найденных фактов или оценка готовности.
Нужна локальная утилита Forma `0.1.5` или совместимая с `graph layer`,
`forma-graph/0.2` и `graph check --require-summaries`.
Если нужной утилиты нет, назови блокер; не скачивай и не обновляй её молча.

## 1. Самостоятельно изучи проект

Прочитай местные инструкции, `index.md`, [[core|ядро]], [[graph|контракт графа]]
и существующие фрагменты. Каталог страниц `PAGES` бери из `.forma/state.json`
(`directory`), не предполагай `.forma`. Пока есть `.forma/pending.json`, остановись.
Вызов skill уже поручает работу: не спрашивай список каталогов и технический бюджет.
Явные ограничения пользователя и проекта имеют приоритет.

Начни с устройства всей репы: документация и доступные обсуждения, пользовательские
сценарии, исходники, тесты, зависимости, конфигурация запуска и сборки.
Охвати все существенные области, не каждую строку. Углубляйся в ключевые пути,
чтобы сопоставить реализацию с замыслом, а не перечислить функции и тесты.
Чтение кода для объяснения проекта — не отдельная детализация подсистем.
При большом объёме запиши конкретные неразобранные области и последствия для выводов.

Сам выбирай безопасные чтения, локальные Git-списки, diff и `--allow-source`.
Штатные проверки карты не требуют повторного разрешения. Дополнительные локальные
тесты и сборку выбирай после чтения команд и условий: запускай, если они безопасны,
не требуют внешних ресурсов, секретов, пользовательских данных и не запрещены явно.
Найденный тест не называй выполненным. Не устанавливай зависимости из сети.
Не читай секреты, `.env`, ключи, личные скрытые каталоги, игнорируемые данные,
зависимости и сгенерированные сборки. Каталог страниц разрешён отдельно.
Не обходи запреты через ссылки. Не меняй приложение и принятые продуктовые правила.
Сеть, внешние репозитории, публикация и перенос в основную копию требуют разрешения.
Если путь к локальной Forma неизвестен из доступной документации, спроси только его.

## 2. Сначала объясни целое

До записи карточек составь короткий связный рассказ по собственным источникам проекта:
что создают, для кого, зачем, как человек этим пользуется и в чём особенность.
Отдельно назови замысел, существующую реализацию и существенный пробел.
Не копируй описание Forma. Не начинай с технологий, файлов или ролей узлов.
Если источников нет или они спорят, сохрани конкретное неизвестное или расхождение.
Обсуждения — свидетельства о словах участников, а не автоматическое принятие решений.

Из рассказа выбери значимые предметы и запиши первый слой. Названия и `summary`
вместе должны объяснять проект без открытия источника только ради ответа «о чём он».
«Понять проект» и «Посмотреть решения» — не описание предмета.
Не требуется шаблон карточек «Цель / Сценарий / Реализация».
Технические детали раскрой через обоснованные связи; не выдумывай их ради связности.

## 3. Обнови карту явно

Используй [[graph|формат `0.2`]]: `concept`, `entries`, `summary`, `about`, `elaborates`.
Исправление плохих входов входит в этот обзор; сохранение ID не замораживает навигацию.
Сначала сопоставь смысл, область и источники с прежними ID.
Не меняй авторство, время, статусы, `run` и основания прежних утверждений на свои.
Новые свидетельства и противоречия добавляй отдельно; история не исчезает при смене решения.
Принятие не следует из наличия кода; тестовый файл не означает успешный запуск.

Для старой карты `0.1` явно сообщи о переходе выбранных фрагментов в `0.2`:
сохрани прежние ID и данные, добавь объяснения с отдельным происхождением,
входы и предметные связи. Это входит в обычное поручение обзора по этому контракту.
Установщик ядра карту автоматически не мигрирует; старые выпуски не переписывай.
Если смена формата или входов запрещена пользователем, соблюди запрет,
назови конкретный блокер и не объявляй первый экран исправленным.

Прочитай источники каждого объяснения, включая прежние и исторические записи.
Не копируй название вместо сути, не усиливай исходное утверждение.
Недостаточно сведений — оставь `summary: null`, перечисли ID, причину и нужный шаг.
Не освежай старые хеши ради зелёной диагностики; для новой версии источника нужен
новый ID, если прежний используется историей или `run.inputs`.
Сохраняй прежнюю запись и причину изменения статуса в связанной странице истории.
Повтор без новых сведений и дефектов не перестраивает карту и не плодит узлы.
Пиши небольшие `graph/*.json` и короткие связанные страницы, не страницу на карточку.
Запиши запросы, решения, охват и результат в журнале источников проекта.
Проверь diff; конкурентные правки перечитай, не затирай.

## 4. Проверь структуру, весь текст и обычный первый экран

Все команды выполняй из локальной Forma. Подставь абсолютный путь проекта `REPO`
и выбранный `PAGES`. Флаги `--allow-source` добавь сам для изученных безопасных
исходников внутри проекта. Получи схемы перед записью; схема `0.1` не изменилась.

```sh
npm run forma -- graph schema --version 0.2
npm run forma -- check "PAGES_ABSOLUTE"
npm run forma -- graph check --repo "REPO" --pages "PAGES" --require-summaries --format json
npm run forma -- graph layer --repo "REPO" --pages "PAGES" --format json
```

Покрытие учитывает всю карту, включая `0.1` и исторические узлы. Пустая карта
или пропуски дают код 2. Исправь ошибки; оставшиеся пропуски назови по ID и причинам,
не объявляй обзор завершённым. Обычный `graph check` без флага допускает старый граф.
Покрытие не доказывает смысловую верность и актуальность оснований.

Начальный слой проверяй без `--id`, `--search`, `--scope`, изменённых лимитов
и смещения. Затем выбери показанный вход и проверь хотя бы один маршрут
`graph layer --repo "REPO" --pages "PAGES" --id ID --format json` к раскрытию
и его основанию. Сам выбери существующие ID. Раскрытие добавляет понимание,
не повторяет оглавление. При необходимости проверь тот же экран в браузере.

По видимым названиям и объяснениям первого экрана письменно ответь:

- Что это за программа и для кого?
- Что человек хочет сделать и как выглядит использование?
- Что отличает этот проект от произвольной репы с документацией?
- Что здесь замысел, что существует и какой существенный пробел остаётся?

Связывай ответы с видимыми карточками, не с прочитанным за кадром документом.
Источник есть, но ответ скрыт в глубине — дефект обзора; исправь в этом запуске
и повтори проверку. Нет источника — покажи неизвестное, не сочиняй цель.
Заполненные `summary` и успешная структура не заменяют эту смысловую проверку.

## 5. Сообщи результат

Покажи названия и краткие объяснения начальных карточек, ответы проверки понятности
и выбранный маршрут к основанию. Назови изменения, источники, прочитанные области,
конкретные пропуски охвата, неизвестное и одну следующую область для уточнения.
Приведи точные команды и результаты, покрытие всей карты и оставшиеся ID отдельно.
Различай структуру, полноту объяснений, актуальность источников, самооценку понятности
и человеческую приёмку. Не выдавай собственную оценку за оценку пользователя.
Недоступная проверка — явное ограничение, а не успешный результат.
Не завершай обещанием «потом улучшить обзор», если это и было поручением.
