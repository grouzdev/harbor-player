# Пульс: финальные работы перед релизом

## Текущее состояние

Рабочая версия реализована. Архитектура и интерфейс описаны в
[плане реализации](pulse-implementation-plan.md).

Подтверждено последним прогоном:

- `npm test`: 40 файлов, 297 успешных тестов.
- `npm run build`, `npm run lint`, `git diff --check`: успешно.
- Выбранный browser-прогон в Chrome и Edge: 16 успешных сценариев,
  включая настоящий аудиоплеер, IndexedDB, переходы, очистку и прокрутку.
- Синтетический read-benchmark: миллион интервалов, 10 тысяч альбомов,
  3634 активных дня, 1000 альбомов в одном дне. Тёплый p95:
  недельное окно — 1,665 мс, статистика альбома — 0,158 мс.
  Это SQLite + сериализация, не полное открытие экрана.

**Релиз пока не готов:** полный `npm run test:e2e` не зелёный.
В полном Chrome-прогоне было 101/107 успешных сценариев. Три ошибки
`networkidle` из-за опроса истории в остановленном плеере исправлены и
перепроверены в обоих браузерах. Расширенный прогон с исключением трёх
известных проблемных сценариев дал 205/208, обнаружив также проблемы
библиотечных фикстур и отдельный сбой проверки закладок в Edge.
Не считать исключения или выборочный прогон заменой полного набора.

## P0 — закрыть до релиза

### 1. Получить полный зелёный e2e-прогон

- [ ] Разобрать `tests/browser/catalog-filters.spec.ts`:
  `filter menu excludes active filters and restores removed filters`.
  Проверить, действительно ли добавление «Недавние» должно открывать
  редактор; сейчас сценарий ждёт кнопку закрытия редактора.
- [ ] Разобрать `tests/browser/library.spec.ts`:
  `topbar groups catalog controls in the requested order`.
  Проверить тот же переход редактора, а затем порядок контролов:
  кнопка Пульса отдельная, кнопка обложки не объединена с ней.
- [ ] Разобрать `local library: readable UI, playback, tags, move and permanent delete`.
  Сверить ожидание снятия выбора библиотеки после выбора артиста с текущими
  правилами сохранения upstream-контекста. Не менять рабочие правила каталога
  только ради старого ожидания теста.
- [ ] Изолировать фикстуру `cover mode shows the album, artwork and quick playback search`.
  Проверить пересечение путей/имён библиотек с предыдущими сценариями:
  подключение сейчас может оставить диалог открытым. Каждый сценарий должен
  явно создавать свой контекст или корректно находить уже подключённую библиотеку.
- [ ] Воспроизвести сбой Edge:
  `bookmark filter retries a failed load and follows external reset`.
  Выяснить, почему не появляется действие «Показать всю музыку»:
  ошибка приложения, условия пустого состояния или зависимость от предыдущих тестов.
- [ ] Добавить регрессионную проверку: остановленный плеер с пустым outbox
  не отправляет запросы истории; pending outbox после перезапуска всё же доставляется.
- [ ] Запустить **без фильтров и исключений** `npm run test:e2e`.

**Приёмка:** Chrome и Edge проходят полностью; причины исправлений понятны.
Не увеличивать timeout и не добавлять skip, чтобы скрыть проблему.

### 2. Проверить надёжность истории при сбоях

- [ ] Отключить локальный сервер во время воспроизведения, накопить несколько
  треков и checkpoint, восстановить сервер, сверить итоговое время.
- [ ] Перезапустить приложение с pending IndexedDB outbox:
  подтверждённые данные не теряются, повторная доставка не удваивает суммы.
- [ ] Закрыть окно после checkpoint и проверить допустимую потерю хвоста:
  около 15 секунд при исправной локальной записи, не обещание lossless.
- [ ] Очистить историю при выполняющемся POST и pending новых ревизиях.
  Старое поколение не должно восстановить очищенную историю.
- [ ] Проверить отключение/повторное включение сбора во время playback;
  время отключённого периода не попадает в новые интервалы.
- [ ] Проверить ошибки открытия/записи IndexedDB, недоступность диска и quota:
  пользователь видит ошибку, pending не теряется молча; после восстановления
  сообщение об ошибке не остаётся навсегда.
- [ ] Проверить несколько окон: нет случайного второго recorder одного
  плеера. Отдельно зафиксировать правило для двух реально одновременно
  проигрывающих сеансов; не дедуплицировать их только по треку.

**Приёмка:** итоговые агрегаты совпадают с принятыми интервалами;
retry, порядок доставки и очистка не меняют смысл истории.

### 3. Уточнить граничные случаи учёта времени

- [ ] Проверить обычную скорость, 0,5×/2×, seek вперёд/назад, repeat-one,
  pause/resume, buffering, error и смену файла при файловой операции.
- [ ] Проверить долгое фоновое воспроизведение, задержки `timeupdate` и таймеров,
  sleep/wake. Подтверждённое продвижение учитывается; сон без продвижения — нет.
- [ ] Добавить тесты субмиллисекундных значений и перевода в целые миллисекунды
  на HTTP-границе: финальная ревизия после checkpoint, отсутствие отрицательного
  прироста, единое время дневных и альбомных агрегатов.
- [ ] Проверить очень короткие интервалы и несколько часов непрерывного аудио:
  части не превышают час и сохраняют один логический визит.
- [ ] Проверить полночь, DST и смену системных часов. История использует
  сохранённый timezone; изменение системной зоны не меняет прошлые дни.

**Приёмка:** паузы/seek не засчитываются, повтор засчитывается,
границы суток и округление не теряют и не удваивают миллисекунды.

### 4. Проверить настоящую миграцию и сохранность данных

- [ ] Открыть копию реальной БД v12 с библиотеками, плейлистами и очередями.
  Подтвердить миграцию в v13 и неизменность каталожных данных.
- [ ] Проверить повторный запуск после миграции и rollback при ошибке.
  Тест с искусственно пониженным `user_version` не заменяет настоящую старую БД.
- [ ] Удалить/переименовать библиотеку, изменить теги и переместить файлы:
  исторический альбом не исчезает, известные aliases сохраняют его ID.
- [ ] Проверить историческую обложку после исчезновения текущего кэша,
  отсутствие файла и ошибку сохранения копии. Название и время должны
  сохраняться даже без доступного изображения.

**Приёмка:** новая история независима от жизненного цикла каталога;
миграция не меняет воспроизведение и существующие пользовательские данные.

## P1 — закончить проверку интерфейса и скорости

### 5. Реальный UI и доступность

- [ ] Вход/выход из панелей и обложки, настройки, Escape вложенного диалога,
  возврат фокуса и прокрутки. Невидимые панели не получают Tab/горячие клавиши.
- [ ] Повторное открытие Пульса восстанавливает дату и альбом;
  очистка убирает старую выбранную карточку и статистику.
- [ ] Пустая история, сбор отключён, ошибка API/обложки, длинные названия.
- [ ] Все альбомы насыщенного дня достижимы мышью и клавиатурой;
  фокус не теряется при виртуализации.
- [ ] Drag с отпусканием вне ленты, pointercancel/lostcapture, колесо на границах,
  трекпад и touch. Ctrl + wheel остаётся масштабированием.
- [ ] 390/640/800/1366/1600 px, низкое окно, portrait/fullscreen,
  тёмная/светлая темы и пользовательский accent.
- [ ] Проверить в установленном Electron-приложении, не только в браузере.

**Приёмка:** верхний альбом/статистика, центральная лента и нижняя шкала
годов видимы без ненужного вертикального скролла; нет фоновой окраски
выходных, заголовка, периодов и светлого участка общего слайдера.

### 6. Измерить end-to-end производительность

- [ ] Повторить `npm run build:server && node scripts/pulse-benchmark.mjs`.
- [ ] Измерить холодное открытие Пульса, тёплый возврат и возврат к панелям
  на целевом устройстве; SQLite-бенчмарк этих операций не измеряет.
- [ ] Проверить UI на десяти годах и 1000 альбомах в дне:
  bounded DOM, число запросов, ограничение LRU и память после долгой навигации.
- [ ] Записать профили drag/wheel и прыжков по годам.
  Устаревшие запросы не возвращают к предыдущей дате; нет длительных задач.
- [ ] Отдельно измерить загрузку/декодирование настоящих обложек:
  при необходимости использовать thumbnail, не оригиналы.
- [ ] Измерить время транзакции ingest батча и влияние на обычные запросы
  каталога. Синхронный `better-sqlite3` не должен надолго блокировать сервер.
- [ ] Зафиксировать рост raw-данных, индексов, WAL и исторических обложек
  на реалистичной частоте прослушивания, а не только синтетической базе.

**Ориентиры, не гарантии:** тёплое открытие/возврат < 100 мс,
холодное открытие < 300 мс на локальном API, read p95 < 50 мс,
без long task > 50 мс во время прокрутки. Объяснить отклонения
и устранить узкое место до заявления о выполненном бюджете.

## P2 — отдельные последующие задачи

- Смена timezone с фоновой пересборкой согласованных поколений агрегатов.
- Явная политика очистки неиспользуемых исторических обложек:
  не удалять ресурсы, на которые ещё ссылается история или каталог.
- Экспорт/импорт истории, если потребуется.
- Retention/компактация raw-интервалов — только после измерений и с явной
  политикой; не удалять источник истины автоматически.
- Управление одновременным воспроизведением в нескольких окнах, если
  продукту нужен ровно один активный сеанс.

Это не причины добавлять новые переключатели дизайна, статистику дня/периода
или переписывать самостоятельный режим обложки.
