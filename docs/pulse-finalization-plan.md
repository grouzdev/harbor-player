# Пульс: финальные работы перед релизом

## Текущее состояние

Рабочая версия реализована. Архитектура и интерфейс описаны в
[плане реализации](pulse-implementation-plan.md).

**Контекст первой поставки:** проект ещё не выпускался, внешних пользователей
нет. Единственная рабочая БД находится на этом ПК и уже имеет схему v13.
Миграция пользовательских установок с v12 и совместимость с ранее выпущенными
версиями не входят в gate этого релиза. Это не разрешение сбрасывать рабочую БД:
текущие каталог, очередь, плейлисты и история должны сохраняться.

Подтверждено текущим прогоном P0:

- `npm test`: 44 файла, 347 успешных тестов.
- `npm run build`, `npm run lint`, `git diff --check`: успешно.
- Полный `npm run test:e2e`, без фильтров/исключений:
  **126/126 Chrome и 126/126 Edge**.
- `npm run test:pulse:process`: настоящий отказ/перезапуск API, два
  playback-окна, восстановление browser profile и точные суммы — успешно.
- `npm run test:pulse:desktop`: свежий packaged Electron, две аварии/restart,
  durable pending и два реально проигрывающих окна — успешно.
- `npm run test:desktop:smoke`: успешно. Это smoke, не проверка crash/sleep/wake.
- `npm run test:pulse:sleep -- --smoke`: harness запускается в изолированном
  packaged Electron, пишет native/IndexedDB/HTTP evidence. Физический сон
  не выполнялся.
- `npm run test:pulse:sleep -- --background-only`: 10 минут реального фона
  успешно; принято 599 876 мс при native elapsed 600 118,6 мс,
  расхождение −242,6 мс при прежнем допуске 1 с. SQL-суммы совпали точно,
  HTTP истории — 200, outbox пуст. Потеря от per-sample jitter исправлена.
- `npm run format:check`: существующий baseline четырёх неизменённых файлов;
  все файлы текущих исходных изменений проходят адресный Prettier.
- Ранее выполненный синтетический read-benchmark: миллион интервалов, 10 тысяч альбомов,
  3634 активных дня, 1000 альбомов в одном дне. Тёплый p95:
  недельное окно — 1,665 мс, статистика альбома — 0,158 мс.
  Это SQLite + сериализация, не полное открытие экрана; в этой работе не повторялся.

**Релиз пока не готов:** e2e и доступные процессные проверки закрыты.
Единственный незакрытый пункт P0 — физический sleep/wake с фоновым playback.
Его выполнение описано в [плане завершения P0](pulse-p0-plan.md#план-завершения-оставшегося-p0):
фоновый сеанс, сон при playback, контрольный сон при pause и сверка evidence.
Поиск пользовательской копии v12 снят как неприменимый к первой поставке.
P1 тоже ещё не закрыт.
Автоматические проверки и их пределы записаны в
[журнале P0](../verification/pulse-p0.md). Выборочный прогон не заменяет полный.

## P0 — закрыть до релиза

Порядок выполнения, точки изменений и доказательства приёмки:
[рабочий план P0](pulse-p0-plan.md). Чекбоксы ниже остаются сводным списком
релизных обязательств; наличие плана не означает их выполнения.
Результаты текущей работы записываются в
[журнале проверок P0](../verification/pulse-p0.md).

### 1. Получить полный зелёный e2e-прогон

- [x] Разобрать `tests/browser/catalog-filters.spec.ts`:
  `filter menu excludes active filters and restores removed filters`.
  Проверить, действительно ли добавление «Недавние» должно открывать
  редактор; сейчас сценарий ждёт кнопку закрытия редактора.
- [x] Разобрать `tests/browser/library.spec.ts`:
  `topbar groups catalog controls in the requested order`.
  Проверить тот же переход редактора, а затем порядок контролов:
  кнопка Пульса отдельная, кнопка обложки не объединена с ней.
- [x] Разобрать `local library: readable UI, playback, tags, move and permanent delete`.
  Сверить ожидание снятия выбора библиотеки после выбора артиста с текущими
  правилами сохранения upstream-контекста. Не менять рабочие правила каталога
  только ради старого ожидания теста.
- [x] Изолировать фикстуру `cover mode shows the album, artwork and quick playback search`.
  Проверить пересечение путей/имён библиотек с предыдущими сценариями:
  подключение сейчас может оставить диалог открытым. Каждый сценарий должен
  явно создавать свой контекст или корректно находить уже подключённую библиотеку.
- [x] Разобрать нестабильное ожидание Edge:
  `bookmark filter retries a failed load and follows external reset`.
  Отдельное старое падение не воспроизвелось; проверено, что действие
  «Показать всю музыку» относится к успешно загруженным пустым закладкам,
  не к ошибке или загрузке. Individual, group и полный Edge проходят.
- [x] Добавить регрессионную проверку: остановленный плеер с пустым outbox
  не отправляет запросы истории; pending outbox после перезапуска всё же доставляется.
- [x] Запустить **без фильтров и исключений** `npm run test:e2e`.

**Приёмка:** Chrome и Edge проходят полностью; причины исправлений понятны.
Не увеличивать timeout и не добавлять skip, чтобы скрыть проблему.

### 2. Проверить надёжность истории при сбоях

- [x] Отключить собственный тестовый процесс локального сервера во время
  воспроизведения, накопить два трека/checkpoint в двух уже буферизованных окнах,
  восстановить SQLite/origin/profile и сверить точные суммы.
  Последовательная смена трека без API не поддерживается и не подменялась mock.
- [x] Перезагрузить browser-приложение с pending IndexedDB outbox:
  подтверждённые данные не теряются, повторная доставка не удваивает суммы.
- [x] Аварийно завершить собственное дерево процессов packaged Electron после
  checkpoint и проверить хвост: в последнем прогоне 4,006 с; подтверждённые
  15 249 мс восстановлены точно. Около 15 секунд — ориентир при исправной
  записи и своевременном checkpoint, не обещание lossless.
- [x] Очистить историю при выполняющемся POST и pending новых ревизиях.
  Старое поколение не должно восстановить очищенную историю.
- [x] Проверить отключение/повторное включение сбора во время playback;
  время отключённого периода не попадает в новые интервалы.
- [x] Проверить управляемые ошибки открытия/записи IndexedDB, серверной записи и quota:
  пользователь видит ошибку, pending не теряется молча; после восстановления
  сообщение об ошибке не остаётся навсегда.
- [x] Проверить несколько настоящих Electron BrowserWindow: нет случайного второго recorder одного
  плеера. Отдельно зафиксировать правило для двух реально одновременно
  проигрывающих сеансов; не дедуплицировать их только по треку.

**Приёмка:** итоговые агрегаты совпадают с принятыми интервалами;
retry, порядок доставки и очистка не меняют смысл истории.

### 3. Уточнить граничные случаи учёта времени

- [x] Проверить настоящее audio на 1×/0,5×/2×, seek вперёд/назад, repeat-one,
  pause/resume, error/recovery и перенос проигрываемого файла; buffering —
  детерминированными тестами адаптера. Смена ключа того же trackId сохраняет визит.
- [x] Проверить 10 минут реального фонового воспроизведения и задержки
  `timeupdate`/таймеров; устранить накопительную потерю и проверить доставку final.
- [ ] Проверить физический sleep/wake: подтверждённое продвижение учитывается;
  сон без продвижения — нет.
  Приёмка — реальный Windows sleep/wake в изолированном packaged Electron,
  включая paused-контроль; CDP freeze не заменяет эту проверку.
  Harness `test:pulse:sleep` готов. Он никогда не усыпляет ПК самостоятельно:
  оба цикла сна запускает только оператор после соответствующего сигнала.
- [x] Добавить тесты субмиллисекундных значений и перевода в целые миллисекунды
  на HTTP-границе: финальная ревизия после checkpoint, отсутствие отрицательного
  прироста, единое время дневных и альбомных агрегатов.
- [x] Проверить очень короткие интервалы и многочасовой accumulator через
  recorder → HTTP → SQLite на управляемых часах: части ≤ часа и один визит.
- [x] Проверить полночь, фактические DST-переходы и инъекцию скачков wall-clock.
  Сохранённая timezone проверена при смене `TZ` процесса; настройки ОС не менялись.

**Приёмка:** паузы/seek не засчитываются, повтор засчитывается,
границы суток и округление не теряют и не удваивают миллисекунды.

### 4. Сохранность текущих данных и независимость истории

- [x] Удалить/переименовать библиотеку, изменить теги и переместить файлы через Catalog:
  исторический альбом не исчезает, известные aliases сохраняют его ID.
- [x] Проверить историческую обложку через storage/API после исчезновения текущего кэша,
  отсутствие файла и ошибку сохранения копии. Название и время должны
  сохраняться даже без доступного изображения.
  Дополнительно настоящий browser UI проверен после удаления обеих тестовых копий:
  HTTP 404 не скрывает название, карточку и статистику.

**Приёмка:** история независима от жизненного цикла каталога и изображений;
перезапуск и файловые операции не теряют подтверждённые данные.

**Снято из P0:** поиск реальной пользовательской v12 и отдельный прогон её
обновления до v13. Такой выпущенной пользовательской базы нет. Имеющиеся
тесты old-code v12 → v13, повторного открытия и rollback сохраняются как
внутренняя регрессия, а не доказательство совместимости выпущенных версий.
Не понижать `user_version`, не создавать искусственный «пользовательский»
backup и не очищать единственную рабочую БД ради закрытия чекбокса.
Перед будущими изменениями схемы делать согласованный локальный SQLite backup
с учётом WAL. Обязательства обновления пользовательских БД появятся после
первой поставки и должны планироваться от реально выпущенной схемы.

### 5. Реальный UI и доступность

### 6. Измерить end-to-end производительность

- [ ] Повторить `npm run build:server && node scripts/pulse-benchmark.mjs`.
- [ ] Измерить холодное открытие Пульса, тёплый возврат и возврат к панелям

- [ ] Проверить UI на десяти годах и 1000 альбомах в дне:
  bounded DOM, число запросов, ограничение LRU и память после долгой навигации.
- [ ] Записать профили drag/wheel и прыжков по годам.
  Устаревшие запросы не возвращают к предыдущей дате; нет длительных задач.
- [ ] Отдельно измерить загрузку/декодирование настоящих обложек:
  при необходимости использовать thumbnail, не оригиналы.
- [ ] Измерить время транзакции ingest батча и влияние на обычные запросы
  каталога. Синхронный `better-sqlite3` не должен надолго блокировать сервер.
- [ ] Зафиксировать рост raw-данных, индексов, WAL и исторических обложек
  на реалистичной частоте прослушивания, а не только синтетической базе.

**Ориентиры, не гарантии:** тёплое открытие/возврат < 100 мс,
холодное открытие < 300 мс на локальном API, read p95 < 50 мс,
без long task > 50 мс во время прокрутки. Объяснить отклонения
и устранить узкое место до заявления о выполненном бюджете.

## P2 — отдельные последующие задачи

- Смена timezone с фоновой пересборкой согласованных поколений агрегатов.
- Явная политика очистки неиспользуемых исторических обложек:
  не удалять ресурсы, на которые ещё ссылается история или каталог.
- Экспорт/импорт истории, если потребуется.
- Retention/компактация raw-интервалов — только после измерений и с явной
  политикой; не удалять источник истины автоматически.
- Управление одновременным воспроизведением в нескольких окнах, если
  продукту нужен ровно один активный сеанс.

Это не причины добавлять новые переключатели дизайна, статистику дня/периода
или переписывать самостоятельный режим обложки.
