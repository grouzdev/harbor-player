# Пульс: технические правила

Справочник вместо завершённого плана реализации. Это не checklist будущих
работ; актуальные задачи находятся в [roadmap](../pulse-roadmap.md).
Точная схема и API определяются кодом и миграциями, а не историческими
предложениями.

## Интерфейс

- Самостоятельный режим рядом с режимом обложки. Постоянный нижний плеер
  продолжает работать; вход/выход сохраняет состояние каталога.
- Непрерывная горизонтальная лента всех календарных дней до сегодня,
  включая пустые. Все альбомы дня видны без «+N»; повторы суммируются,
  порядок задаётся первым прослушиванием.
- Ширина дня зависит от числа альбомов; пустые дни уже. Высота столбиков
  фактически прослушанного времени имеет единый масштаб для всей истории.
  Длинное прослушивание не обрезает столбик и не уменьшает обложку.
- Единый фон, разделители дней, без окраски выходных. Сверху выбранный альбом
  и его статистика, ниже лента и календарная полоса годов, внизу плеер.
- Выбор альбома не меняет воспроизведение. Навигация по дате не меняет выбор.
  Полоса годов имеет равномерный календарный масштаб независимо от ширины дней.
- Drag фона использует pointer capture и корректно завершается на
  pointerup/cancel/lostcapture. Обложки остаются кликабельными; touch нативный.
  Wheel нормализует pixel/line/page deltas; горизонтальный trackpad не
  суммируется с вертикальным. Ctrl+wheel остаётся масштабированию.
- Нет статичных инструкций «нажми/листай», переключателей области статистики
  и отдельного заголовка Pulse. Контролы имеют доступные имена.

## Семантика истории и статистики

- Считается реально прошедшее время подтверждённого воспроизведения, не длина
  перемотки. Pause/buffering/seek не добавляют время; повтор фрагмента добавляет.
  При 2× одна минута реального прослушивания остаётся одной минутой.
- Все положительные интервалы входят во время, без скрытого порога зачёта.
  Длительности — целые миллисекунды; округление только при отображении.
- Моменты записываются в UTC; календарные дни — в сохранённой IANA timezone.
  Полночь делит вклад, DST не позволяет считать любой день равным 24 часам.
- Статистика альбома: время за всю доступную историю, число дней, возвращения
  в тот же день, доля времени в выбранном дне, первое/последнее появление.
  Это не «первое прослушивание в жизни» и не статистика загруженного окна.
- Возвращение — новый альбомный блок после другого альбома или разрыва сессии,
  не heartbeat/следующий трек того же альбома/короткая пауза. Другой день
  увеличивает число дней, не same-day returns.
- Разрыв сессии: 30 минут без воспроизведения или новый запуск приложения.
  Исторический album ID и снимок метаданных/обложки переживают удаление файла.
  Одинаковые теги сами по себе не основание сливать разные издания.
- История локальная; отключение сбора и очистка с подтверждением обязательны.
  Дата начала покрытия явная; прежнее прослушивание не восстанавливается.

## Запись, доставка и чтение

- Один recorder рядом с постоянным audio, не внутри экрана Pulse.
  Аккумулятор в памяти; `timeupdate` не пишет HTTP/SQLite.
- Checkpoint примерно каждые 15 секунд обновляет накопительную revision
  одного event ID, а не создаёт строку на heartbeat. Pause/seek/source/rate
  разделяют интервалы; длинный непрерывный участок ограничен часом.
- IndexedDB outbox хранит последнюю накопительную версию события. Только ACK
  конкретной revision позволяет удалить её; новая pending revision остаётся.
  Retry с backoff, ограниченные batches, не большой JSON в localStorage.
- Источник истины — интервалы в существующей SQLite; дневные/альбомные агрегаты
  обновляются атомарно в той же короткой транзакции. Duplicate/stale версии
  не меняют суммы, конфликт payload одного ID не получает молчаливый ACK.
- Обычное открытие читает агрегаты и bounded страницы, не сырые интервалы
  за всю историю. Тяжёлые rebuild/export/VACUUM не идут на обычном read path.
- Очистка меняет history generation: старый outbox не воскрешает историю.
  Новая эпоха сбора не импортирует старые pending события неявно.
- Архив обложек адресуется содержимым, не событием; filesystem copy не входит
  в write-транзакцию. Ownership предшествует работе сервиса и staging recovery.
  Recovery удаляет только однозначно owned staging, не чужие/опубликованные
  изображения, symlink/junction или неоднозначные entries.
- Checkpoint ограничивает crash-потерю только при исправной локальной записи.
  `pagehide` — best effort, не обещание lossless. Ошибка outbox не скрывается.

## Границы производительности и доказательств

Ориентиры: cold dataReady p95 < 300 мс, warm/return < 100 мс,
catalog read p95 < 50 мс, отсутствие long task > 50 мс при прокрутке.
Latency samples и диагностические traces учитываются раздельно.
Generated fixtures, CDP rendering opportunity, JS heap, synthetic input
и unpacked automation не подменяют originals, hardware paint, GPU memory,
физические устройства и установленную ручную приёмку.

Raw-интервалы и используемые исторические изображения не удаляются скрытой
retention/GC. Новые метрики, жанры, «альбом целиком», рейтинги запусков,
экспорт и смена timezone не добавляются ради завершения текущей приёмки.
